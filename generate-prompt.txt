# Paper Trading Dashboard - Complete Implementation Prompt

## Overview
Build a paper trading dashboard that consumes trading signals from a Telegram channel, executes paper trades, tracks positions, and closes them when stop loss (SL) or take profit (TP) levels are hit. The application must include a real-time dashboard showing XAU/USD price, open trades, trade history, P&L, and system status.

## Core Features

### 1. Telegram Integration

- **Single Channel Architecture**: Start with one configurable channel, but design for easy expansion to multiple channels
- **MTProto Authentication**:
  - `GET /auth/request?phone={phone}` - Initiates auth, sends code to user's Telegram
  - `GET /auth/verify?code={code}` - Verifies code and completes authentication
  - Phone number stored in `.env` file
  - Session persisted to file (`session.json` or SQLite) so re-authentication isn't needed on restart
- **Signal Consumption**:
  - Listen for new messages and message edits in the configured channel
  - Parse trade signals using configurable templates (see Configuration section)
  - Detect initial signal (e.g., "gold buy 4556") and updated signal with SL/TP

### 2. Price Feed (XAU/USD)

- **API Selection**: Use a reliable free-tier API (e.g., MetalPriceAPI, GoldAPI.io, or similar) that supports at least 1-second update frequency
- **Polling Interval**: 1 second or less
- **Fallback Behavior**: If API fails, use last known price and display a warning on the dashboard via status chip
- **Symbol Format**: Handle the API's expected format (XAU/USD, XAUUSD, or GOLD)
- **WebSocket Alternative**: If the API supports free WebSocket, use it instead of polling

### 3. Trade Logic

#### Entry Rules
- Parse initial signal to extract: action (BUY/SELL), symbol, max entry price
- **Entry Price Validation**: Do NOT enter if current price exceeds max entry price (for BUY) or is below min entry price (for SELL). Reject and log if breached.
- **Position Sizing**: Fixed lot size from `.env` (future: configurable via dashboard or message)

#### SL/TP Handling
- Parse edited message to extract SL and TP levels
- **Multiple TP Levels**: Use only the lowest TP level for exit
- **Timeout Handling**: If SL/TP not received within 5 minutes of trade entry:
  - Mark trade with warning status in UI
  - Provide "Close Trade" button for individual trades
  - Provide "Auto Close All Faulted" button to close all trades missing SL/TP after 5 minutes
- **Trade Exit**: Close entire position when SL or TP is hit (no partial closes)

#### Concurrent Trades
- Support multiple open trades simultaneously
- Each trade tracked independently

### 4. Dashboard (Frontend)

#### Theme & Layout
- **Color Scheme**: Green and black programmer aesthetic
  - Primary: Neon green (#00ff00 or similar)
  - Background: Dark (#0a0a0a, #111)
  - Accents: Dark green, gray
- **Responsive Design**: Works on desktop and mobile

#### Dashboard Widgets
1. **Real-Time Price Display**: Large, prominent XAU/USD price with last update timestamp
2. **Service Status Chips**: Visual indicators for:
   - Telegram connection status (connected/disconnected/warning)
   - Price API status (connected/disconnected/warning)
   - Trading status (active/paused)
3. **Open Trades Table**:
   - Columns: Symbol, Action, Entry Price, Current Price, SL, TP, Lot Size, P&L (USD), P&L (%), Status, Actions
   - Real-time updates via WebSocket or polling
   - Close button for manual exit
   - Warning indicator for trades missing SL/TP after 5 minutes
4. **Trade History Section**:
   - Closed trades with exit reason (SL hit, TP hit, manual close, fault timeout)
   - Filterable by date, symbol, action
5. **P&L Display**:
   - Total P&L in USD
   - Total P&L in percentage
   - Today's P&L
6. **Equity Curve Chart**:
   - Line chart showing account equity over time
   - Time range selector (1D, 1W, 1M, All)
7. **Log Viewer Window**:
   - Scrollable log display
   - Filter by log level (INFO, WARN, ERROR)
   - Auto-scroll to latest option
   - Clear logs button

### 5. Backend API

#### Authentication Endpoints
```
GET /auth/request?phone={phone}
  - Sends verification code to Telegram
  - Response: { success: true, message: "Code sent to +1234567890" }

GET /auth/verify?code={code}
  - Verifies code and completes MTProto auth
  - Response: { success: true, session: {...} } or { success: false, error: "Invalid code" }
```

#### Trade Endpoints
```
GET /api/trades/open          - List all open trades
GET /api/trades/history       - List closed trades (with filters: ?from=, ?to=, ?symbol=, ?action=)
POST /api/trades/:id/close    - Manually close a trade
POST /api/trades/close-faulted - Close all trades missing SL/TP after 5 minutes
```

#### Price Endpoints
```
GET /api/price/current        - Get current XAU/USD price
WS /ws/price                  - WebSocket for real-time price updates
WS /ws/trades                 - WebSocket for trade updates
```

#### System Endpoints
```
GET /api/status               - Get system status (Telegram, Price API, Trading)
GET /api/logs                 - Get recent logs (with level filter: ?level=INFO)
```

### 6. Logging System

- **Library**: Winston with file transport
- **File Location**: `logs/app.log`
- **Behavior**: Append-only with automatic purging when exceeding 1000 lines
- **Log Levels**: INFO, WARN, ERROR
- **Non-Blocking**: Use async file writing
- **Dashboard Integration**: Logs streamed to dashboard log viewer via API endpoint

## How to Configure Trade Message Templates

### Step 1: Understand the Pattern Syntax
Patterns use JavaScript RegExp syntax. Key elements:
- `^` and `$` - Start and end of message
- `\\s+` - One or more whitespace characters
- `([\\d.]+)` - Capture group for numbers (price values)
- `(buy|sell)` - Capture group for action keywords
- `i` flag - Case insensitive matching
- `[\\s\\S]*?` - Match any characters (including newlines) non-greedily

### Step 2: Define Extraction Rules
Each capture group is mapped to a field:
- `group`: Which capture group number (1-based)
- `transform`: How to process the value
  - `uppercase` - Convert to uppercase
  - `parseFloat` - Convert to number
  - `parseRange` - Parse "4553-4556" into { min, max }

### Step 3: Test Your Configuration
Use the examples array to document test cases. The system will validate against these.

### Step 4: Symbol Mapping
Map channel-specific symbols to your internal format:
```json
"mapping": {
  "GOLD": "XAUUSD",
  "XAUUSD": "XAUUSD"
}
```

### Common Patterns

**Simple Signal**: `gold buy 4556`
```regex
^(gold|xau)\\s+(buy|sell)\\s+([\\d.]+)$
```

**Detailed Signal**: `GOLD BUY NOW\nBuy at 4553-4556\nSL 4546\nTP 4559`
```regex
(gold|xau)\\s+(buy|sell)[\\s\\S]*?buy at\\s+([\\d.\\-]+)[\\s\\S]*?sl\\s+([\\d.]+)[\\s\\S]*?tp\\s+([\\d.]+)
```

## Error Handling

### Telegram Disconnection
- Show warning on dashboard via status chip
- Attempt auto-reconnect with exponential backoff
- Log disconnection event

### Price API Failure
- Show warning on dashboard via status chip
- Continue using last known price
- Log failure event

### Trade Execution Errors
- Paper trades: Close using last known price
- Log error with full context
- Notify via dashboard (trade status shows "Closed at last known price")

### Missing SL/TP Timeout
- After 5 minutes without SL/TP:
  - Mark trade with warning status
  - Enable manual close button
  - Enable "Auto Close All Faulted" button
